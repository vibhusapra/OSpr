Research + implementation / October 22, 2026

A voice tool that belongs on your Mac.

OSpr v0 combines native dictation workflows with accelerated local speech models. The goal is ambitious: match the useful capabilities of the best tools, then win on accuracy, latency, privacy, reliability, and design.

Developer preview. Full union parity and a top-three product ranking are not established. The core implementation and reproducible model tests are real. Live microphone/insertion acceptance is pending because this Mac locked during the build. What to build around

Local Parakeet for fast English/European dictation; Whisper and Qwen for broader coverage and quality tradeoffs. Keep a strict raw transcript, deterministic vocabulary, reliable insertion and an optional refiner.

This is an inference from OSpr’s measurements and the models’ documented language coverage, not a universal winner declaration.

Where the product competition moved

Many competitors now bundle meetings, agents, mobile, sync and organization controls. Free local dictation and BYOK are already common. A generic “Whisper plus a hotkey” is not enough differentiation.

OSpr needs a better complete writing loop: fast start, dependable end, faithful edits, recoverable failures and no surprises about data routing.

Measure the engine. Then measure the whole tool.

The English test slices select the first five utterances per speaker by archive path, before inference: 200 clean clips from 40 speakers, and 165 difficult clips from 33 speakers. Separate regression fixtures cover 73 read-speech clips plus noise, quiet audio, silence and a concatenated long recording. FLEURS adds ten clips in each of Spanish, German, Hindi, Japanese and Mandarin.

Comparison boundary: these are local inference backends, not Wispr Flow, Superwhisper, Handy or other product timings. OSpr wall times include audio preparation and inference, but omit microphone capture, hotkey delivery, IPC, rewriting and insertion. whisper.cpp includes persistent-server HTTP and WAV transport. Cold starts exclude model download. No energy, thermal-isolation or end-to-end product ranking is claimed.
Backend / modelCasesError rateWarm p50Warm p95RTFColdPeak GPU*Raw

Lower is better. WER lowercases and removes punctuation; CER also removes whitespace consistently, including character-spaced FLEURS references. Chinese/Japanese whitespace WER is not interpreted. Errors include numerals, abbreviations and spelling differences; no model-specific normalizer. *GPU allocator peak and OS process RSS are different measurements. Small score gaps do not establish significance. Timings are exploratory, with background desktop activity and no calibrated energy sampler.

Pin the machine, power mode, app/model versions, corpus digest, language, hotkey and cleanup settings. Replay the same public speech through a loopback input for dictation-only apps; use equivalent file import separately. Timestamp audio start, first visible partial, speech end and final inserted text. Run cold trials and at least 30 warm repetitions. Score raw recognition separately from formatting, number/name preservation, corrections, failures, memory and energy. Record capture/endpointing delay; do not compare a decoder-only number to a product’s advertised end-to-end number.

The protocol is ready; equivalent commercial-product runs are not complete. Do not place OSpr on a public ASR leaderboard using these partial-corpus numbers.

Raw fresh-process trials

Meeting notes that quote their source.

A local 4B model selects numbered source excerpts; OSpr checks their exact source spans and stores a source fingerprint. It generates no paraphrased facts. All required deadline/price/negation/injection sentinels survived in 4/4 synthetic cases. Selection can still omit context and important commitments; natural-meeting relevance is not established. This is an extractive aid, not a complete abstractive summary. Inputs and selected excerpts.

Text refinement is still a fidelity risk. In twelve synthetic text cases, exact factual sentinels passed 8/12 for Qwen3 1.7B and 9/12 for Qwen3 4B Instruct. Both failed cases. Added commentary can pass substring checks, and dictated prompt injection is a real failure in the raw outputs. Refinement defaults off; raw text and native preservation guards remain essential. Read the complete outputs.

Privacy boundary

Default ASR and text rules are local. Local MLX rewriting remains local. BYOK audio and text routes are separate, visible settings; provider keys go to Keychain. HTTPS is required except loopback, redirects are rejected, and provider error bodies are not surfaced.

History uses owner-only atomic JSON files in Application Support. Capture uses private temporary audio. Completed takes are copied to an owner-only recovery slot before inference and deleted after successful transcription or explicit discard. Failed takes survive restart until retried/exported/discarded. No analytics or background content collection is included.

No claim of application-level history encryption, enterprise compliance, or complete network sandboxing. FileVault and the chosen provider’s policies remain separate.

Recovery and maintainability

The native app, CLI, MCP adapter and benchmark harness share the engine contract. Request IDs prevent response mixups; generations fence stale output; timeouts and cancellation terminate the owned worker. Raw and edited transcripts remain distinct.

Weights and package versions are pinned. The local process is replaceable with a Swift MLX/Core ML implementation after equivalent tests. No local inference HTTP service or persistent network credential is required.

The small development build uses its checkout. An optional self-contained bundle passed moved-path/offline smoke tests for all five engines. Signing/notarization and update recovery remain release work. Completed takes now survive inference failure/restart in a private recovery slot; retry/export/discard interactions still need device acceptance.

MCP tools expose local-file transcription, model listing and supplied-text rewriting. They do not expose microphone capture, UI control, transcript history or the user’s clipboard. Enabling that adapter in a client is a separate, deliberate installation.

Close the release gates, then customize

A path from credible v0 to a leading tool.

Release acceptance

  1. Unlock and validate microphone permission, start/stop/PTT, device switching, interruption, HUD and failure recovery.
  2. Exercise insertion in TextEdit, a browser, a code editor, secure fields and a moving cursor; verify clipboard restoration.
  3. Validate the implemented native incremental stream, speaker-labeled imports, dual-track desktop capture and local excerpt notes before claiming interaction parity.
  4. Validate the bundled app on a clean Mac; sign/notarize and exercise install/uninstall, upgrade and login item behavior.
  5. Replay identical tasks in actual competing apps and publish raw, versioned measurements with correction effort and energy.

Training and model surgery

  1. Build an opt-in, consented dictation corpus: Indian/other accents, code-switching, names, paths, numbers, disfluencies, noise, silence and short turns.
  2. Split by speaker/session/device; isolate a sealed test set. Keep public benchmark audio out of fine-tuning and model selection.
  3. Try vocabulary/context biasing and calibration before training. Compare LoRA and targeted decoder/encoder changes against the same fidelity gates.
  4. Distill a fast streaming student from stronger ASR teachers with explicit error review. Preserve timing, corrections, punctuation and abstention examples.
  5. Only then prune heads/channels, quantize sensitive layers separately, distill the refiner and profile Metal/ANE kernels. Keep licenses and model/data provenance in the release.
Proposed winning axis: a native, fast, trustworthy writing loop with open measurements and no account requirement. Usefulness and reliability should be obvious in a five-minute trial; model novelty alone is not the product.
